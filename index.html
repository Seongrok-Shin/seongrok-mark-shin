Regional Order Processing & Multi-Database Synchronisation Re-engineering

Problem

Regional branches suffered from heavy page load times (~10 minutes for large order sets) and concurrency conflicts when updating stock across 8+ independently running regional MariaDB databases.

What I Built

Implemented server-side pagination with ASP.NET Core and Razor. Re-architected multi-master data synchronisation routines, automated order-entry workflows with pre-configured defaults, and integrated HERE Location API for geocoding validation.

Impact
  • >90% page load reduction: dropped from ~10 mins to under 1 min.
  • 80% faster processing: order-entry reduced from 5 mins to <1 min.
  • Eliminated concurrent-update conflicts across 8+ regional database instances.
C#ASP.NET CoreRazorAzure SQLMariaDBHERE Location API

Key Technical Decisions

  • Data Sync: Implemented idempotent synchronization workers with version-based conflict resolution, preventing concurrent branch updates from corrupting central inventory.
  • Server-side Pagination: Shifted heavyweight SQL aggregation from in-memory processing to indexed SQL cursor/offset queries, eliminating browser memory thrashing on legacy branch workstations.
  • Address Normalisation: Integrated the HERE API directly into REST validation pipelines before saving to SQL tables, ensuring downstream transport drivers received validated GPS and road data.
